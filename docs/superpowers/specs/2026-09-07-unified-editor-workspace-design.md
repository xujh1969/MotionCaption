# MotionCaption 统一编辑器工作台设计

日期：2026-09-07

## 目标

以 MotionCaption 为唯一产品界面，保留其精品动效库，并迁入 CaptionForge 的视频、字幕、工程编辑和透明导出能力。界面不再分成独立“编辑器”和“组件实验室”；所有操作在一个工作台完成。

支持两条同等重要的使用路径：

1. 完全手工：空工程中挑选组件、编辑内容与时间、导出透明视频。
2. AI 编排：内置 LLM 或安装了组件 skill 的外部 Agent 选择现有组件并生成 JSON 序列；程序校验通过后直接覆盖当前全部动效。

视频和字幕均为可选输入。新工程默认 1920×1080、30fps、10 秒。

## 统一布局

采用可折叠四区布局：

- 顶部工具栏：载入视频、导入字幕、导入 Agent JSON、AI 编排、同步组件 Skill、打开工程、保存工程、工程设置和透明导出。工具栏保持单行紧凑高度，不放工程状态文字。
- 左侧特效栏：搜索框、列表内分类分割条和密集组件项。分类不使用下拉框，组件项不显示长说明。
- 中间视频栏：唯一合成画布；显示参考视频、动效和编辑覆盖层。
- 右侧属性栏：编辑所选组件的内容、位置、缩放、时间、轨道和 zIndex。
- 底部时间轴：只读字幕参考轨和多条可编辑动效轨。

左右栏可折叠。时间轴取消高度滑动条，改用顶部水平分隔线拖动高度；高度限制为 140px 至工作区高度的 60%，双击分隔线恢复默认高度。取消页面级“编辑器/组件实验室”切换。

## 画布

画布始终使用工程坐标系。默认预览透明棋盘，也可切换为当前 MotionCaption 深色背景；载入本地视频后还可切换为参考视频。三种背景只影响编辑预览，不能进入透明导出结果。

参考视频是可选对齐素材。视频文件、对象 URL 和本机路径不进入工程 JSON。

视频画布上方不保留单独状态栏。工程/参考视频状态和画布参数显示在画布底部控制条左侧，例如 `空工程 · 无参考视频 | 1920×1080 · 30fps`。播放/暂停按钮固定在控制条水平正中，时间和帧数右对齐；控制条常驻，鼠标经过时增强亮度，但不自动隐藏，也不占用工作区布局高度。时间轴画布裁剪播放头溢出，播放头停在末帧时不产生横向滚动条。

动效与视频在同一个画布中合成。编辑选择框属于独立覆盖层；组件实现和正式 Remotion 合成不持有鼠标状态。导出时不渲染选择框。

点击按 zIndex 和视觉顺序命中实例。标题与半环等同时间组件可分别选择、拖动和四角等比缩放。修改一个实例不能改变其他实例的 props。点击视频画布上非实例的区域（背景或留白）、时间轴空白处，或按 Escape 都会取消当前选中（模态对话框打开时 Escape 交给对话框处理）。画布选择层必须开启 pointer-events，使空白处点击能可靠命中 `data-selection-layer` 的取消处理器。

## 特效添加与属性编辑

左侧单击组件后，立即使用注册表默认内容和默认变换在当前时间创建正式实例；新实例自动选中，右侧立即显示其属性。组件栏不保留单独的“添加到当前时间”按钮。实例立即进入画布和时间轴，不存在手工组件的草稿阶段。

右侧属性栏沿用注册表 legacy 属性定义渲染全部可调字段（`src/app/PropertyPanel` 嵌入）。文本行一级只显示文案输入框，行尾 `T` 展开该行“文字详情”：字号、颜色与透明度，以及重点文字 `{{重点}}` 的字号/颜色与透明度；独立样式字段（组件背景色等）与 list 条目（增删改）在同一面板中直接可见。`posX/posY/scale` 由“变换”区接管（写入 `transform`），属性面板不再重复暴露。内容字段、样式字段、位置、缩放、起止时间、轨道和 zIndex 均写回正式 `MotionProject.effects`。任何更新都需保持工程 Schema 有效，并限制在工程时长和画布边界内。

### 样式同步、全局默认与语义调色板

针对从不同参考视频模仿而来的组件配色不一致问题，属性面板顶部提供三个互不冲突的快捷动作；面板底部折叠区提供跨组件的语义调色板。

| 动作 | 作用 | 关键限制 |
|---|---|---|
| 存为默认样式 | 把当前实例的完整快照写入本机 `localStorage` 的 `motioncaption.styleDefaults.v1`：样式键（颜色、字号、透明度）、内容键、数组条目，以及 `posX/posY/scale`（取自当前变换 `transform` 的实际生效值，保存用户调好的视觉位置与大小） | 「同步到同类组件」仍只覆盖样式键，不动内容与位置缩放 |
| 同步到同类组件 (N) | 把当前实例的样式键覆盖到工程内所有 `componentId` 相同的其他实例；需两次点击确认 | 不覆盖内容键与 transform；标题（10x标题）数量为 0 时按钮禁用 |
| 重置默认 | 把本实例所有键还原为当前生效默认：内容回内置，样式键回 `motioncaption.styleDefaults.v1`（无记录则回内置） | 立即生效，不弹窗 |

新建实例（手动拖入 / AI 导入）时 `addEffect` 与 `compileDraft` 都会把 `motioncaption.styleDefaults.v1[componentId]` 叠入实例 `props`，使"系列视频"自动延续用户调好的风格；手动拖入的新实例会按默认快照中的 `posX/posY/scale` 初始化变换（`addEffect` 内有画布越界/footprint 缩放钳制），AI 编排路径的落位仍由 `placementPreset` 决定，不受用户默认位置影响。语义调色板（`paletteSlots.ts`）定义 8 个槽位（`accent / accent2 / emphasis / title / body / label / bg / border`），把全部组件的颜色键人工归类；渐变两端、多序列、状态色等不可单槽表达的键不映射，保留组件原值。面板「调色板 · 统一全片配色」折叠区可：①「从当前组件提取」按声明顺序取每槽第一个映射键的当前色写入选中调色板；②修改任一槽后「应用到全工程 (N)」一次性把所有实例的映射键颜色铺开；调色板与样式默认均存于 `localStorage`（`motioncaption.palette.v1`），跨工程共用。

## AI 编排与 Agent JSON

AI 只编排已有组件，不生成新的视觉组件代码。左侧栏只展示组件库；顶部 `AI 编排` 按钮打开轻量弹窗，显示字幕数量、组件库版本、模型配置和可选风格要求。

内置 Agent 使用 OpenAI-compatible API。Base URL 和模型名可保存为普通设置；API Key 存入系统凭据库，不写入 localStorage、日志、工程 JSON 或错误信息。正式网络请求由 Tauri 原生命令或受控 sidecar 发出，前端不能读取明文 Key。请求层使用可替换 Provider，浏览器开发和自动测试使用假 Provider，不调用真实收费 API。

内置 Agent 输入当前字幕、画布参数、组件库版本、用户风格要求和组件选择摘要。它使用与外部 skill 同源的结构化 manifest；选定组件后再加载对应 reference，避免每次请求携带全部组件的完整说明。模型输出只按 strict JSON 解析，绝不执行其代码或命令。

字幕/文案中的汉字数字（一百五十、百分之二十）在特效展示字段中统一使用阿拉伯数字（150、20%）。责任在生成端：编排链路喂给模型前把字幕数字归一为阿拉伯（cuesBlock），skill 工作流第一步要求模型先扫描字幕、把表数量的汉字数字转换为阿拉伯，再基于转换后的理解做编排与溯源。字幕原文保持汉字不变。导入校验不再做数字/单位溯源检查（2026-09-08 产品决策：避免误报触发二次 LLM 修复调用），数字正确性由生成端提示词约束，编造数字不再被程序拦截。

编排规则约束：标题字段精炼（中文 ≤12 字、不加逗号断句、枚举用数字标识）；两侧优劣/数量对比并强调某一方的内容必须选可并列呈现双方的组件（t3-03/t7-01/t7-02/fx-08/t5-*），不得压进单行标题组件（t1-*、fx-01/fx-02/fx-05）。

列表/步骤/卡片/流程类组件的条目支持**逐条出现时机**（2026-09-08）：列表条目可携带可选数值字段 `at`（单位秒，相对该组件场景起点的偏移），条目在该时刻出现而不是按组件内置的均匀节奏依次刷屏。`at` 是渲染层契约字段，不属于锁定样式。编排端被要求**尽量为每个条目设置 at**：凡是内容对应到某条被引用字幕的条目都必须填 `at = (该字幕 startMs − 场景最早引用字幕 startMs) / 1000`（1 位小数），并把这些字幕写入 sourceCueIds；仅无法对应具体字幕的总结性条目才省略，禁止编造与字幕无关的等距数值。skill 侧以指令式措辞 + 带字幕时间的计算示范 + 示例 JSON 内嵌 at 演示值三重强化（模型实测曾因"可选、不清就省略"措辞而一律不填）。导入校验放行 `at`（数值或可解析字符串须 ≥0，null/空串视为未设置不报错）；编译时透传与规范化，不能用样本默认值覆盖 AI 编排意图；渲染层由共享 helper `atFrames` 统一换算（`at × 30` 帧），`at` 缺失时回退组件原有均匀节奏，旧工程行为完全不变。共 22 个列表类条目数组支持（fx-04/06/07/08、t3-04、t4-01/02、t5-01~06、t6-01/02/05/06/07、t7-01/02/03/05）；fx-05 标签排与 t7-04 数值序列无逐条入场语义，不参与。属性面板列表编辑器为每行提供「出现时间(秒)」输入列（留空 = 匀速），可手动微调。

首次输出出现硬错误时，程序把结构化错误反馈给 LLM，并自动修复一次。第二次仍失败则停止，显示错误，当前工程保持不变。零硬错误时直接原子覆盖当前 `project.effects`；软警告仅展示，不阻止导入。生成期间继续显示旧动效。

外部 Agent 可安装导出的组件 skill，自行生成同格式 JSON，再由顶部 `导入 Agent JSON` 入口载入。

程序导入 JSON 时依次执行 strict schema、组件与版本、字段类型、字幕来源、列表容量和排他冲突校验。全部通过后，确定性编译并原子覆盖当前 `project.effects`；无需草稿状态或二次确认。

Agent JSON 支持自包含导入：draft 可选携带顶层 `cues` 数组（与生成时所用字幕逐字一致）。携带时导入会自动重建工程字幕轨，并把工程时长延长到全部场景所需帧数，因此**导入 Agent JSON 前无需先导入 SRT、也无需载入视频撑开时长**；空工程（默认 300 帧/10 秒）可直接导入并预览。未携带 `cues` 的旧格式 draft 仍按原逻辑依赖工程内已有字幕。

Agent JSON 支持同刻多轨分层：一个 scene 的 `components` 可含 2-3 个组件在同一字幕区间同时播放，多个 scene 也可引用同一段/重叠的字幕区间来叠层——确定性编译把重叠效果自动分配到不同轨道（每个组件即一个独立实例，可分别编辑轨道与 zIndex）。skill 与内置编排的提示词要求分层时用不同 `placementPreset` 分占屏幕区域并区分 `role`，同一时刻控制在 2-3 层。

组件复用不做硬性次数/相邻限制，判断权交给 AI 按内容形态决定：一组可列表化表达且观点多于 3 条时，应合并进一个支持数组的列表/卡片/流程组件一次性表达，而不是用同一个组件多次重复地逐条堆叠；观点 ≤3 条或场景结构确实不同时，允许跨场景复用同一组件。仅保留一条软性底线——避免某个组件包办整片绝大多数场景，此时改用语义最接近的其他组件。

校验失败时显示完整错误列表，当前工程保持不变。删除 `draftEffects`、`draftReview`、`applyDraft` 和 `discardDraft` 等持久草稿状态及其界面。

## 组件 Skill 生成与同步

`EffectDefinition` 及组件旁的 AI 元数据是组件能力的唯一来源。生成器产出：

- 根 `SKILL.md`：组件编号、适用场景和选择规则。
- `references/<组件ID>.md`：参数、类型、默认值、容量、限制和示例。
- 内置 Agent 使用的结构化 manifest。

生成文件提交到 Git 以便审查，但禁止直接编辑。`npm run generate:skill` 重建产物，`npm run check:skill` 检查注册表、元数据、references 和 manifest 是否一致。组件参数或行为改变时提升 `componentVersion`；组件库增删时提升 `libraryVersion`。Agent JSON 携带版本，程序拒绝不兼容输入。

由于新组件通常由 AI 直接生成代码，顶部提供 `同步组件 Skill`，打开一个同步弹窗：

1. 扫描组件目录和 registry，识别新增、删除、版本与参数变化。
2. 从组件代码、Prop 类型和默认值提取可确定的结构信息。
3. 调用 LLM 起草适用场景、语义角色、容量、限制和示例。
4. 弹窗按"新增 / 变更 / 移除 / 未注册 / 无变化"分组预览差异；AI 元数据建议单独一组，可编辑但默认不勾选。
5. 用户确认后调用原生命令以临时文件 + 原子重命名更新生成物，再运行一致性校验；移除与 AI 建议必须显式勾选。
6. 任一步失败时保留旧 skill，不产生半更新状态。

弹窗底部提供模型 API Key 配置（仅桌面端可见）：Key 只写入系统凭据管理器（服务 `motioncaption.llm`），界面只显示"是否已配置"，永远不出现在工程文件、Skill 产物或错误信息中。浏览器模式下弹窗只读，无法应用或导出。

未注册或 AI 元数据未确认的新组件可以手工使用，但不能进入 AI 编排候选。设置界面显示当前 skill/library 版本，弹窗内可一键导出最新版 skill 文件夹（`SKILL.md` + `references/` + `scripts/`，优先复制 `generate:skill` 的产物），供其他 Agent 工具安装。

Skill 校验器双轨分发：组件选型、复用规则等知识随 `skill/` 目录自包含分发，而 Agent JSON 校验分别由两处同一逻辑源提供——工程内 `scripts/validate-agent-draft.mjs`（Vite 加载 TS 实时校验）与工程外独立包 `skill/scripts/validate-agent-draft.mjs`（esbuild 将共享内核 `src/project/validateDraftCore.ts` + zod 内联为无依赖单文件，运行时读取同目录 `validation-meta.json` 组件元数据快照）。独立包因此只需 Node 即可执行，接收方无需项目源码。内核唯一：程序内 `validateAgentDraft` 为薄封装，规则全部收敛于 `validateDraftCore`；`scripts/generate-skill.mjs` 从 TS 定义裁剪出 `validation-meta.json` 纳入产物一致性检查；`src/project/standaloneValidator.test.ts` 逐字节断言独立产物与程序内校验一致，防止两边规则漂移。

桌面端（Tauri 2）下 AI 编排的补全请求经原生命令发出：Rust 读取 Key 并附加 `Authorization: Bearer`，前端只持有 Base URL 与模型名；原生态强制响应体上限与超时，所有错误先脱敏再返回。浏览器模式回退到注入的脚本 Provider。

## 时间轴

顶部保留只读字幕参考轨；下方每个正式组件实例是独立时间块。同场景组件可共享起止区间，但仍是可独立编辑的实例。

时间块支持选择、整体移动、调整起止边界和切换轨道。时间不得为负、越过工程末尾或产生零长度。

轨道较多时，轨道内容区纵向滚动；时间轴放大后，内容区横向滚动。时间标尺在纵向滚动时保持顶部可见，轨道名称在横向滚动时保持左侧可见。滚轮/滚动条不能改变工程数据。播放头、字幕和组件块共享同一时间比例。

时间轴右上角常驻缩放控件：缩小/放大按钮统一使用放大镜内嵌 +/− 描边图标（`src/editor/Timeline.tsx` 的 `ZoomGlyph`），重置按钮显示 `1:1`；按钮高度 24px、宽 24px。高度只能通过顶部拖拽分隔线调整，不显示高度 range 输入。

每条轨道左侧显示眼睛图标。关闭后该轨道内容不消失，而是以变暗方式呈现：时间轴上的组件块降透明度并去饱和，编辑画布中的实例同步变暗显示，字幕层同理；隐藏轨的实例不参与画布选中与编辑。可见性只属于编辑器状态，不修改工程实例，也不影响透明导出。时间轴显示自适应时间刻度和当前播放头，绘制与缩放/横向滚动保持对齐，可参考旧 CaptionForge 的刻度步长和播放头方法。刻度按整秒标注；时长不是整秒倍数时，末尾秒只标注一次（如 623 帧 ≈ 20.77 秒，末尾只保留一个 0:20）。

所有可滚动控件使用统一深色主题滚动条，包括组件栏、属性栏、时间轴横纵区域和弹窗。滚动条保持细窄，轨道与滑块使用面板色，悬停使用主题强调色，不允许深色界面出现系统浅色滚动条。

## 工程持久化

工程保存为 strict `captionforge.project` JSON，包含画布参数、字幕和正式组件实例，不包含本地视频文件或路径。

打开工程时先检查 kind、版本和 Schema；失败返回可展示错误，并保证当前工程对象不变。

## 透明导出

透明导出只渲染正式组件，不包含参考视频、棋盘/深色预览背景、鼠标覆盖层或编辑器 UI。

浏览器 Web Renderer 已在真实验证中因 `t7-06` 丢失 SVG 半环而被否决。正式实现继续使用可替换 `RenderBackend`，下一候选为 Node/Remotion sidecar，优先透明 MOV。后端不支持或导出失败时明确报错，不静默降级为黑底或不透明视频。

## 验收

- 单页四区工作台可用；折叠侧栏、调整时间轴高度和双向滚动不造成页面溢出。
- 空工程无需视频或字幕即可添加、编辑、保存、打开和导出组件。
- 标题与半环同时显示，并可分别点击、拖动、缩放、编辑文字、时长、轨道和 zIndex。
- 棋盘、深色和参考视频预览可切换，均不进入透明导出。
- 字幕参考轨只读；多条动效轨可编辑，纵向和横向滚动正确。
- 每轨眼睛只控制编辑预览；时间刻度和播放头在缩放、横向滚动后仍准确。
- 所有滚动区域使用与深色主题一致的滚动条。
- 合法 Agent JSON 直接覆盖全部动效；非法 JSON 被拒绝且工程不变。
- 自包含 Agent JSON（携带 `cues`）可导入全新空工程：自动生成字幕轨、自动延长工程时长，无 SRT、无视频也能预览。
- 内置 AI 编排读取字幕并自动导入；首次硬错误自动修复一次，最终失败不改变工程。
- `同步组件 Skill` 能识别新增/变化组件，预览 AI 起草的元数据，并以原子方式更新生成物。
- 生成 skill、references 与内置 manifest 和 registry 保持版本一致；外部 Agent 生成的 JSON 可导入。
- T1、T2、T7 代表组件完成入口、中间、稳定和结束前四帧视觉检查，以及白/黑/彩底 Alpha 检查。
- 自动测试、类型检查、构建和真实浏览器交互验收全部通过。

## 非目标

- AI 编排不创建新的组件代码，只选择并参数化已注册、元数据已确认的组件。
- 同步组件 Skill 不静默批准 AI 推断的语义元数据。
- 不恢复低质量 CaptionForge 组件库。
- 不在本阶段测量 45 个组件的精确 DOM 边界；碰撞预警使用注册表声明的保守 planning footprint。
- 不让编辑预览背景进入成片。
