# t3-04 - 多行key-value数据条目

- Component version: 1
- Use for: Multi-row key-value data display with 2-4 rows.
- Avoid: Avoid narrative paragraphs, processes, timelines, and more than 4 rows.
- Motion feel: —
- Capacity: 2-4 items

## Editable content

Only the following keys may appear in `content`. All style and component layout properties are locked and must not be supplied by an Agent.

- `rows`: array of objects { d: 说明 (string), k: 名称 (string), v: 数值 (string) }; required: yes; default: `[{"d":"超低运行延迟","k":"延迟","v":"8ms"},{"d":"低功耗运行","k":"功耗","v":"12W"},{"d":"超高识别精度","k":"准确率","v":"99.6%"},{"d":"做出解释","k":"参数","v":"100"}]`; semantic role: items; constraints: 2-4 items; all listed item fields are required strings.
- `titleText`: text; required: yes; default: `"核心参数指标"`; semantic role: title; constraints: none beyond the declared type.

## Per-item timing (`at`)

Each item in `rows` carries a numeric `at` field — the item's appearance time in **seconds, relative to the scene's earliest cited cue start**. Items appear at their `at` time instead of the default even rhythm.

- **Every item that corresponds to one cited cue MUST get an `at`.** Compute it from the cue start times: `at = (cueStartMs − earliestCitedCueStartMs) / 1000`, rounded to 1 decimal. Include every cue you used in the scene's `sourceCueIds`.
- Worked example: a scene cites cues starting at 9800ms / 15600ms / 21400ms (earliest = 9800) and its rows rows visualize them → `at` values are `0`, `5.8`, `11.6`. The first item is `0`, and each later item appears exactly when its cue begins to be spoken.
- Omit `at` ONLY for an item that is a general summary not tied to any single cue (rare). Do NOT leave `at` out of items just to be safe, and do NOT invent evenly spaced values that no cue supports.
- `at` must be a number ≥ 0 (never a string, never negative, never beyond the scene duration). The example JSON below shows the field shape — replace the demo values with cue-derived ones.
